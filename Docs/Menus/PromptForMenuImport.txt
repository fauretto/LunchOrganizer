Inside this folder @D:\Data\GitPerso\LunchOrganizer\Docs\Menus there is a file named Menus_A4_Paysage_Chaque_Semaine_Au_Coeur_De_France.docx. This file is a template, each month we receive the same file with different menus related to the working days of the month. This file contains several pages. Each page contains an header and a table. Each table refers to a working week of the month. Each table is organized in this way : 
- each row correspond to a day in a week
- each column correspond to a menu (Menu 1 , Menu 2, Menu 3, and so on)
- the first column of each table contains the information related to the day of the week and its related date (DD.MM). The year is not specified
- each cell of the table contains the description of a menu
The idea here is to find a way to parse this file and be able to extract all the menus for each day specified in the rows of each page and populate the dbo.menus table of the lunchorganizer database accordingly.
The Administration page should have a button named 'Import menu' in the top section of 'Menu & Prices' tab which allow the user to select a word file having respecting this format and located wherever in the PC. As the year is not specified in the rows, the application should ask the user to select the year to which the file refers to. This information must be used to correctly generate the menu_date field of the dbo.menus table. Obviously, the code must be able to recognize the weeks whicg start in the year specified by the user and finish in the next year : typical case is the last week of the year, in which the a working week can belong to the last week of the year and some days belong to the current year and some day to the nex year.
The import must be rolled back in case of whatever error, the database cannot contain partial data coming from the import. The result of the import (pass or fail) must be highlighted to the user with an appropriate message .
In case some (or all) menus to be imported already exist in the database, this must be considered as an error to be highlighted to the user with an appropriate message and rolled back in the database.
